# UI Direction — 商い帖

`anti-ai-slop-ui` のプロセスに沿って、販売管理デモの UI をレビューし、方向性・トークン・レイアウトを再定義した記録です。

参考:
- [Michelin Design System — Principles of a dashboard](https://designsystem.michelin.com/data-visualization/design-guidelines/principles-of-a-dashboard)
- Adobe Color パレット `30F08E, F06530, F0305F, 4F705F, 70584F`

## 1. 分類とプロダクト文脈

- **UI 分類**: 業務アプリ / 管理ダッシュボード / 入力画面
- **プロダクト**: 見積〜締処理までを扱う販売管理システムのデモ
- **利用者**: 中小企業の経理・営業事務・管理者
- **主な行動**: 今日の数字を確認する、伝票を探す、見積・受注を起票する、入金・締処理を進める
- **情報密度**: 高め。一覧性と正確さを優先する
- **信頼要件**: 高め。金額・日付・残高の読み違いが起きないこと
- **プラットフォーム**: Web（デスクトップ中心、タブレット・スマートフォンまで）
- **トーン**: 落ち着き、実務的、帳簿的。装飾より記録性

## 2. レビュー結果（変更前）

### 診断

清潔で破綻はないが、白い角丸カード、等間隔の KPI 6 枚、色付きの漢字チップ、ティールのアクセント、ピル型タブという構成で、一般的な管理画面テンプレートの印象が強い。販売管理・帳簿というプロダクト固有の視覚言語が弱い。

### 検出した generic tells

- 同じ形・同じ重さの KPI カード 6 枚
- 色付きの「売・入・掛・残・仕・払」チップ（装飾としての色分け）
- 角丸 12px のカードとピル型の状態バッジ
- ティール＋スレートの、どの SaaS にもある配色
- ピル型のナビゲーション
- システムフォントのまま、数値・ラベル・本文の型階層が弱い
- 一覧が白いカード＋グレー罫線の標準テーブル
- 余白がカードの反復で決まっており、帳簿のリズムがない

### スコア（変更前）

- AI Slop Score: **7 / 10**
- Distinctiveness Score: **3 / 10**

## 3. 採用した方向性

**Michelin operational dashboard × Ledger**（Michelin のデータビズ原則＋帳簿構造）。

- Michelin の原則に合わせ、**統一したライトグレー背景**と**白いカード**を使う
- フィルタ領域はカードと異なるグレー面にして、操作とデータを分ける
- 最重要情報を左上〜上部に置く（KPI ストリップ → 売上推移 → 対応待ち → 台帳）
- 色は装飾ではなく情報。売上・仕入・入金・督促・危険を意味で割り当てる
- 角丸をほぼ廃止し、1px の罫線で情報を区切る
- KPI はカードの集合ではなく、連続した「帳票ストリップ」
- 一覧は台帳のような高密度テーブル。数字は等幅数字、伝票番号はモノスペース
- グラデーション、グロー、絵文字、ガラス表現は使わない
- ヘッダーは要望どおりサンセリフの「販売管理システムデモ」を維持

### カラーの意味

| 色 | 用途 |
| --- | --- |
| `#4F705F` | 売上、受注済、完了、ポジティブ |
| `#F06530` | 主要アクション、未処理、商品別ランキング |
| `#F0305F` | 危険、マイナス、フォーカスリング |
| `#70584F` | 仕入、提出済、ニュートラル寄りのデータ |
| `#30F08E` | 当月の売上バー、入金の強調（文字色には使わない） |

> 主要ボタンは `#F06530` のままだと白文字のコントラストが不足するため、同じ色相を暗くした `#B8461C` を面に使い、白文字を載せています。`#F06530` はバー・下線・ステータスの面に残しています。

## 5. レイアウト戦略

- **Dense Dashboard + Ledger** を採用。
- 上部: 日付とクイックアクションを 1 本の罫線でまとめる。
- KPI: 6 枚のカードではなく、縦罫線で区切った 1 本のストリップ。各セルに 01〜06 の番号を付け、帳票の項目らしくする。
- 中段: 売上・仕入の推移（ワイド）と対応待ち（ナロー）を非対称に配置。
- 下段: 得意先別・商品別・伝票ステータスを 3 枚のカードにせず、1 枚の台帳パネル内の 3 列に分割。
- 一覧: 角丸カードを廃止し、検索・絞り込み・新規作成を台帳のヘッダーとして配置。行は高密度、重要な列は折り返さず、操作列は右側に固定。
- 明細: デスクトップは表、モバイルはカード型。入力は四角いフィールド。
- モバイル: KPI は 3→2→1 列、台帳パネルは 2→1 列。

## 6. 実装メモ

- `src/ledger.css` を `styles.css` の後に読み込み、方向性の上書き層として分離。
- KPI の漢字チップを削除し、CSS カウンタで 01〜06 を付与。
- `dash-grid-3` の 3 カードを、1 枚の `.ledger-card` + `.ledger-grid` に変更。
- 一覧の操作列を `position: sticky` で右固定。
- 文字サイズを約 10% 引き上げ、KPI・表・フォームの可読性を調整。
- 主要ボタンはコントラスト確保のため `#B8461C` の面に白文字。`#F06530` はデータ面に残す。
- 900px 以下では件名列を省略し、操作列の固定も解除して横スクロールを優先（列の重なりを防ぐ）。
- ステータスは角丸ピルではなく、四角いスタンプ＋小さなドットに変更。
- グラフは売上 `#4F705F`、仕入 `#70584F`、当月の売上だけ `#30F08E` のフラットバー。グラデーションなし。
- ナビはピルではなく下線タブ。
- ツールバーは検索を下線フィールド、絞り込みを四角いセレクト、主要操作を `#F06530` のボタンに変更。

## 7. スコア（変更後）

- AI Slop Score: **3 / 10**
  - Palette 0: Michelin のグレー背景＋白カード＋指定パレットで一貫。紫/グラデーションなし
  - Layout 1: KPI ストリップと台帳パネルで独自性。チャート/一覧は標準構造を残す
  - Component 0: 角丸カード・ピル・影を排除
  - Typography 1: システムサンセリフは意図的。モノスペース数字で識別性を追加
  - Decoration 0: グロー・ブロブ・過剰モーションなし
- Distinctiveness Score: **8 / 10**
  - Product fit 2: 帳簿・販売管理の文脈に合う
  - Visual system 2: 色・罫線・角丸・数字のルールが一貫
  - Layout character 2: KPI ストリップと台帳パネルが構造として機能
  - Typographic identity 1: まだ改善余地あり（日本語書体の選択）
  - Signature moments 1: 01〜06 の KPI 番号と操作列固定

## 8. アクセシビリティ確認

- テキストと背景のコントラストを確保（インク `#1a1a1a` / 背景 `#f3f3f3`、カード `#ffffff`）。
- フォーカスリングを朱色で明示。
- 状態は色だけでなくラベル（下書き / 提出済 / 受注済 など）でも表示。
- テーブルはキーボードでスクロール可能。操作列は右固定。
- モバイルでも主要操作（新規作成・検索）を先頭に残す。
- `prefers-reduced-motion` を尊重し、アニメーションを実質無効化する。
- グラフは装飾ではなく、数値と月ラベルを併記。

## 9. 検証

- ローカル / 本番とも 6 KPI、台帳パネル 3 列、ランキング 10 行を確認。
- グラデーション 0、絵文字アイコン 0。
- 本番 `/styles.css` / `/ledger.css` / `/app.js` は `200`、CSP / nosniff / SAMEORIGIN を確認。
- ブラウザコンソールエラー 0。
- 390px / 320px で KPI は 2 列 / 1 列、台帳パネルは 1 列、ページ全体の横スクロール 0。
- 一覧は 900px 以下で件名列を省略、操作列の固定を解除。703px では件名以外の列が収まり、390px / 320px では表内スクロールで全列に到達できる。

## 10. 残課題

- 日本語書体をもう一段強くするなら、ライセンス済みの和文書体を self-host する。
- 一覧の列幅はデータ量に応じた調整が必要。
- 印刷帳票は別の紙面設計（A4）として維持し、画面 UI とは分けて考える。
- 明細の並べ替えはタッチ / キーボード対応が未完了（コードレビュー M-7）。
